Глоссарий Limerence: основные термины

Здесь собраны основные термины, которые встречаются в Limerence и статьях Справочного центра.

Если вы только начинаете пользоваться ботом, необязательно запоминать всё сразу.

Главное для начала:

Тема = отдельная история.

Модель = ИИ, который пишет ответ.

Промпт = ваши постоянные инструкции этой истории.

Память = то, что Limerence сохраняет о произошедшем сюжете.

Лор = заранее заданный канон мира и персонажей.

Остальное спокойно приходит по мере использования.

Аккаунт

Ваш пользовательский профиль Limerence, связанный с Telegram-аккаунтом.

На уровне аккаунта хранятся, например:

  • статус Premium;
  • тариф DeepSeek;
  • подключённые API-провайдеры;
  • библиотека Character Cards;
  • персоны;
  • сохранённые пресеты;
  • общие пользовательские настройки.

При этом сами игровые истории разделены по Темам.

Группа

Приватная Telegram-группа, в которой обычно происходит игра.

Группа может содержать множество Тем.

Сама группа не является одной большой историей Limerence.

Например, внутри одной группы можно иметь:

Адриан — основной сюжет

Адриан — AU

Маркус

Тест Gemini

и каждая из этих Тем будет отдельной историей.

Подробнее: Темы, группы и команды.

Тема / Topic

Один Telegram Topic внутри игровой группы.

Тема — основная единица истории в Limerence.

У неё свои:

  • сообщения;
  • память;
  • настройки;
  • промпт;
  • модель;
  • лор;
  • персона;
  • Character Card;
  • пресет;
  • состояние сцены.

Поэтому /undo, /clear, /lore и большинство игровых команд работают именно с текущей Темой.

История

Игровая сессия Limerence, связанная с конкретной Темой.

В обычной речи «Тема» и «история» часто почти взаимозаменяемы, но технически:

Тема — пространство в Telegram;

история — сохранённая Limerence игровая сессия внутри него.

Ход

Один шаг ролевой игры.

Обычно:

сообщение игрока → ответ модели

образуют один игровой обмен.

В контексте тарифов DeepSeek «ход» обычно означает успешно сгенерированный игровой ответ.

Модель

AI-модель, которая генерирует ответ персонажа.

Например, это может быть модель семейства:

  • DeepSeek;
  • Claude;
  • Gemini;
  • OpenAI;
  • другая модель через совместимого провайдера.

Модель отвечает именно за генерацию текста.

Limerence при этом предоставляет вокруг неё:

  • память;
  • историю;
  • лор;
  • карточки;
  • управление контекстом;
  • интерфейс;
  • другие функции.

Провайдер

Сервис, через который Limerence получает доступ к AI-модели.

Например, один провайдер может предоставлять сразу десятки разных моделей.

Поэтому:

провайдер ≠ модель.

Условно:

OpenRouter — провайдер.

конкретный Claude через OpenRouter — модель.

Провайдеры настраиваются через:

/api

API

Интерфейс, через который Limerence отправляет запрос AI-сервису и получает ответ.

Пользователю обычно не нужно разбираться в техническом устройстве API.

Достаточно понимать:

свой API позволяет использовать собственный доступ к моделям через Limerence.

API-ключ

Секретный ключ вашего аккаунта у API-провайдера.

Он подтверждает:

запросы можно оплачивать и выполнять от имени этого аккаунта.

API-ключ нужно хранить как пароль.

Не публикуйте его в:

  • чатах;
  • скриншотах;
  • промптах;
  • баг-репортах.

Добавление и управление ключами:

/api

Подробнее: Модели и API-ключи.

DeepSeek в Limerence

Готовый режим игры через DeepSeek, для которого пользователю не обязательно иметь собственный API-ключ.

У DeepSeek также есть отдельные настройки отыгрыша:

  • жанр;
  • темп;
  • инициативность;
  • второстепенные персонажи;
  • откровенность;
  • другие параметры.

Не путайте их с универсальными настройками генерации вроде Temperature.

Premium

Основная подписка на Limerence после завершения пробного периода.

Premium даёт доступ к самому продукту и позволяет продолжать играть, в том числе используя собственные API-провайдеры.

Это не то же самое, что оплата самой AI-модели у стороннего API-провайдера.

Подробнее: Доступ, подписки и оплата.

Пробный период / Trial

Период, в течение которого новый пользователь может попробовать полноценный Limerence до покупки Premium.

Отсчёт начинается после первого успешного игрового ответа, а не просто после открытия бота.

Промпт

Постоянные пользовательские инструкции конкретной истории.

Например, в промпте можно описать:

  • персонажей;
  • стиль;
  • POV;
  • правила поведения;
  • устройство мира;
  • ограничения отыгрыша;
  • желаемую манеру повествования.

Промпт передаётся модели каждый ход.

Персонажа совершенно нормально описывать прямо в промпте — Character Card для этого не обязательна.

Подробнее: Промпт для ролевой игры.

Системный промпт

Инструкции системного уровня, которые помогают определить поведение модели.

В Limerence часть системной логики формируется самим продуктом.

Дополнительные системные инструкции также могут присутствовать, например:

  • внутри Character Card;
  • внутри SillyTavern-пресета.

Не путайте системный промпт карточки с вашим обычным промптом истории.

Заметка автора / Author Note

Короткая инструкция для текущего состояния или ближайшей части истории.

Например:

Адриан уже понял, кто предатель, но пока скрывает это.

или:

Сцена должна оставаться камерной и напряжённой.

Если промпт задаёт общие правила истории, Заметка автора удобна для текущего акцента.

Контекст

Вся информация, которую модель получает непосредственно для текущего ответа.

В контекст могут попадать:

  • системные инструкции;
  • ваш промпт;
  • недавняя история;
  • память;
  • найденный лор;
  • Character Card;
  • персона;
  • Заметка автора;
  • другие служебные инструкции.

Важно:

то, что Limerence хранит информацию, ещё не означает, что вся она целиком попадает в каждый запрос модели.

Память диалога

Настройка объёма недавнего динамического контекста, который Limerence может использовать при генерации.

В интерфейсе встречаются варианты вроде:

15K

25K

35K

50K

Это не размер всей долговременной памяти и не лимит промпта.

Подробнее: Расширенные настройки истории.

Память Limerence

Система, которая сохраняет важную информацию о том, что произошло непосредственно в этой истории.

Например:

  • события;
  • отношения;
  • важные решения;
  • изменения;
  • факты о персонажах.

Она нужна, чтобы длинная история не зависела только от нескольких последних сообщений.

Память и лор — разные вещи.

Лор

Заранее заданная информация о мире, персонажах, местах, организациях, правилах и других элементах канона.

Например:

Совет Семи управляет вампирскими кланами.

Блэкхолл принадлежит семье Валленов с XVII века.

Адриан боится огня после пожара 1814 года.

Лор обычно описывает:

что является каноном мира.

Память описывает:

что произошло непосредственно в текущем RP.

Подробнее: Лор и канон.

Lorebook / Лорбук

Организованный набор карточек лора.

Каждая запись может иметь:

  • ключи;
  • текст;
  • значимость;
  • дополнительные параметры активации.

Хороший lorebook работает как система контекстных знаний, а не как один гигантский текст.

Карточка лора / Lore Entry

Одна отдельная запись lorebook.

Например:

Ключи:

Совет Семи, Совет

Текст:

Совет Семи управляет европейскими вампирскими кланами...

Когда тема становится актуальной, запись может попасть в контекст модели.

Ключи лора

Слова или понятия, которые помогают определить, когда карточка лора становится актуальной.

Например:

Элизабет

Совет Семи

Блэкхолл

Красная зима

Ключи — это не просто название карточки.

Они помогают Limerence понять:

когда эту информацию стоит показать модели.

Постоянный лор / «Добавлять всегда»

Карточка лора, которая не ждёт обычного срабатывания по контексту и добавляется значительно стабильнее.

Используется для особенно фундаментальных правил.

Например:

Вампиры этого мира не сгорают на солнце.

Не стоит делать постоянным весь lorebook: тогда пропадает смысл контекстного подключения лора.

Значимость лора

Приоритет карточки, если одновременно подходит слишком много информации.

Обычно:

  • низкая;
  • обычная;
  • высокая.

Это не показатель того, насколько запись «хорошая».

Это подсказка:

чем можно пожертвовать раньше, если для всего найденного лора не хватает места.

Лор-файл

Большой .txt, .md или другой поддерживаемый документ, используемый как база знаний.

Limerence не отправляет весь файл модели каждый ход.

Он ищет подходящие фрагменты и передаёт только часть материала.

Поэтому большой лор-файл лучше представлять как:

библиотеку с поиском

а не:

огромный промпт, который модель всегда читает целиком.

Поиск по смыслу

Способ находить информацию не только по точному совпадению слов, но и по смысловой близости.

Он особенно важен для больших лор-файлов и других поисковых систем Limerence.

Например, сцена может быть связана с понятием, даже если точное название из файла в ней не написано.

World Book

Распространённый формат lorebook из экосистемы SillyTavern.

World Book может содержать множество записей с:

  • ключами;
  • приоритетами;
  • условиями активации;
  • постоянными записями;
  • другими продвинутыми настройками.

Limerence умеет импортировать совместимые World Books.

Character Book

Lorebook, встроенный непосредственно в Character Card.

Он может содержать информацию, связанную именно с этим персонажем:

  • родственников;
  • организации;
  • места;
  • события прошлого;
  • правила мира.

Поэтому некоторые сложные Character Cards без своего родного Character Book действительно теряют значительную часть задуманного поведения.

Character Card / Карточка персонажа

Структурированное описание персонажа.

Она может содержать:

  • имя;
  • описание;
  • характер;
  • сценарий;
  • первое сообщение;
  • примеры диалогов;
  • альтернативные приветствия;
  • дополнительные инструкции;
  • Character Book.

Character Card — удобный переносимый формат.

Но использовать карточку необязательно: персонажа можно описать прямо в промпте.

Подробнее: Персонажи и карточки.

Tavern Card

Общее название карточек персонажей в форматах, происходящих из экосистемы Tavern / SillyTavern.

Они часто распространяются как:

  • PNG;
  • JSON.

Внутри PNG может быть не просто картинка, а встроенные данные персонажа.

Persona / Персона

Описание персонажа игрока.

Это ответ на вопрос:

кем в истории являюсь я?

Например:

Алиса Моррис, 24 года, реставратор...

Не путайте:

Character Card

→ персонаж, которого обычно отыгрывает модель.

Persona

→ персонаж пользователя.

Freeform / Без карточки

Режим игры без активной Character Card.

Персонаж и правила могут быть полностью описаны:

  • в промпте;
  • в лоре;
  • непосредственно в истории.

Это полноценный способ игры, а не «неправильно настроенная карточка».
